## 一、赛题背景

量化研究需要在每个交易日收盘后对股票池做出判断。本题以沪深300为固定股票池，要求参赛者在 T 日收盘后预测未来一周的相对强弱，并直接给出一个可评分的持仓组合。

比赛形式对标大数据挑战赛：主办方提供截至 T 日的沪深300行情快照，参赛者在 T 日收盘后从 300 只成分股中**最多选出 5 只**、分配合计 100% 的权重，持有到 T+5，按组合收益评分。

## 二、任务

- **股票池**：沪深300成分股 300 只，以 `universe.csv` 为准，不得增删或替换。
- **决策时点**：T = 评测快照最后一个交易日（2026-12-04）收盘后。开发阶段使用截至 2026-10-30 的快照，评测时主办方挂载截至 2026-12-04 的快照；两种情况下都只能使用截至 T 日收盘可得的行情。
- **测试窗口**：T+1 至 T+5，即 2026-12-07 至 2026-12-11。
- **持仓约束**：最多选 5 只股票；每只权重非负；权重合计为 1。
- **个股收益**：`open(T+5) / open(T+1) - 1`，即 T+1 开盘买入、T+5 开盘卖出。
- **组合收益**：`score = Σ weight_i × return_i`，测试窗口结束后统一计算。
- **提交次数**：每支队伍只提交一次，提交后不能根据测试窗口行情调整。

## 三、数据

主办方提供开发用冻结快照 `hs300_snapshot_20261030.zip`（截至 2026-10-30），解压后 `data/` 目录包含（字段名见文件表头）：

| 文件 | 说明 |
| --- | --- |
| `train.csv.gz` | 300 只成分股日线，后复权 |
| `universe.csv` | 股票池，300 只 |
| `index.csv` | 沪深300指数日线 |
| `calendar.csv` | 交易日列表 |
| `meta.json` | 来源、复权方式、截止日 |

数据说明：

- 开发快照区间为 2018-01-02 至 2026-10-30，评测快照区间延至 2026-12-04；两者文件结构与字段完全一致。价格已后复权，停牌日无记录。
- 每份快照均在自身最后交易日收盘后冻结，**不含该日之后的价格**；评测快照不含 2026-12-04 之后的价格。
- 可补充公开数据（行业、财务等），但须**截至 T 日可得、可复现，并说明来源**；禁止付费数据、券商数据及任何测试窗口信息。

## 四、提交内容

### 1. Docker 镜像

提交 `docker save` 导出的 tar（如 `team01.tar`）。评测时：

- 数据快照挂载到 `/app/data`（只读），输出目录挂载到 `/app/output`（可写）；
- 评测时挂载的是截至 2026-12-04 的快照；入口脚本应根据挂载数据自行确定预测日，**不要把 2026-10-30 写死**；
- 容器在**无网络**环境下启动，入口自行指定，结束后读取 `/app/output/result.csv`；
- 全部计算在容器内完成，不得依赖外部服务；
- 参考资源 **8 小时、16 GB 内存、10 核 CPU**；镜像需支持 `linux/amd64`，超时或报错视为无效。

### 2. 代码仓库

包含数据读取、清洗、特征、训练、预测与评分脚本，附依赖版本、运行命令与随机种子。**仓库中不得包含真值文件或任何可还原真值的文件。**

### 3. 结果文件

`result.csv` 使用 UTF-8 编码，两列，1–5 行。要求：

- 股票代码为 **6 位字符串、保留前导零、不得重复**；
- 权重非负且**合计为 1**；
- 不得有空值；股票须来自股票池。

```csv
stock_id,weight
300433,0.4
002558,0.3
301236,0.3
```

### 4. 项目结果报告

不超过 2 页，说明**数据口径、验证方案、特征与模型、回测结果、风险与局限**。

### 5. 团队信息

仓库文档中写明队伍成员与分工，见[根目录组队要求](../README.md#组队要求)。

### 6. 答辩演示 PPT

无具体模板要求，随代码仓库一并提交。

## 五、评测

- **主指标**：测试窗口组合收益，越高越好。
- **辅助指标**：组合相对 300 只股票等权平均的超额收益。
- **排名**：按组合收益从高到低；同分时比较超额收益。
- **综合评定**：单期只持有 5 只股票，结果受个股事件影响很大，最终成绩同时参考滚动回测、代码质量与报告，**避免单周运气决定名次**。
- **无效提交**：文件格式不合规、代码重复或不在股票池、权重为负或合计不等于 1、容器超时或未生成结果、使用测试窗口信息、结果无法复现。

## 六、规则与边界

- 禁止针对测试股票池手工指定预测或硬编码结果。
- 结果须可复现；抽查不一致按未提交处理。
- 本题仅用于算法能力考核，所有预测**不构成投资建议**。

## 参考实现

题目附带一份可直接运行的参考实现（baseline），位于 [`baseline/`](./baseline/)，使用 35 维技术特征与 LightGBM，按周采样训练，取预测最高的 5 只等权持有，并附 5 日反转与随机选股对照、年度滚动回测、Dockerfile 与评分脚本。

baseline 只作为**起点与对照**，直接提交 baseline 原样结果大概率只能拿到中等偏下的成绩。在它之上做特征、模型、组合构建上的改进，并清楚说明改进与回测依据，是本题的主要空间。

阅读与运行方式见 [`baseline/README.md`](./baseline/README.md)。注意其中的命令均以 `baseline/` 为工作目录执行。

## 评定说明

不设公开分数细则，评审综合判断，除[根目录的通用维度](../README.md#评定说明)外，本方向额外关注：

- 测试窗口组合收益与相对全池等权的超额收益；
- 验证方案是否可信：时间序列切分有没有泄漏、是否做了滚动回测、结论是否被单期噪声误导；
- 特征与模型的选择是否有依据，改进是否可解释，而不是盲目堆叠或调参碰运气；
- 提交链路是否规范：镜像能否按约定挂载运行、`result.csv` 是否合规、结果能否复现；
- 报告是否诚实：风险与局限写没写、回测与实盘差异有没有交代；
- 代码工程质量：结构、依赖、随机种子与可复现性。

## 注意事项

1. **先跑通 baseline，再谈改进**。能稳定产出合规的 `result.csv` 和可用的镜像，比一个跑不起来的"高级模型"重要得多。
2. **警惕数据泄漏**。快照里不含 T 之后的价格，但特征构造时很容易不小心用到未来信息（比如用当周的未来数据算归一化），回测虚高往往来自这里。
3. **单期结果噪声极大**。5 只股票一周的收益主要由个股事件驱动，不要用一次回测结果判断模型好坏，也不要为了测试窗口"押注"。
4. **提交前本地按评测方式跑一遍**：只读挂载数据、无网络、输出到 `/app/output/result.csv`，确认容器能在时限内完成。
5. **真值文件不要进仓库**，包括回测用的私有真值、评分脚本依赖的答案文件。
6. 镜像为 `linux/amd64`，在 ARM 机器（如 Apple Silicon）上构建时注意加 `--platform linux/amd64`。

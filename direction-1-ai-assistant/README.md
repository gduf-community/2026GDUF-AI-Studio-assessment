# 方向一 · AI 应用：二选一

本方向考察**把一个 AI 应用从想法做到能用**的能力：需求收敛、大模型 / 多模态能力的调用、结构化数据与业务逻辑的落地，以及最终交付的完整度。

## 选题 A：个人记账与消费分析 AI 助手

**定位**：仿 FinTechathon「银行 AI 智能体」的思路，但下沉到个人财务场景，门槛更低、数据自己造。

**领域边界**：只做个人消费与记账，**不做**真实银行接口、不做资金交易与转账。

**必做清单（至少打通 3 个）**：

1. **自然语言记账** + 小票 / 截图 OCR 录入；
2. **消费自动分类与统计**；
3. **自然语言查账**，例如「我上个月吃饭花了多少？」；
4. **预算设定与超支提醒**。

**发挥空间**：理性消费与理财小建议；多轮追问与澄清（信息不全时主动反问）；可视化报表；对诱导性、越界请求的拒绝边界（比如让它「帮忙找贷款口子」该怎么回应）。

**最小基线**：大模型 + OCR / 视觉大模型 API + 结构化存储（如 SQLite）+ 简单图表。自己造一份示例账单 CSV，就能先把链路跑通。

**横向比较关注点**：自然语言查账的理解质量、分类准确率、录入体验、可视化效果。

## 选题 B：学习辅导 AI 助教（限定学科自选）

**定位**：针对**某一门课或一个学科**做「答疑 + 错题 + 练习」的闭环助教，而不是泛泛的通用问答。

**领域边界**：任选一门基础课（高数 / 线代 / 英语 / C 语言 / 数据结构等），**只做这一门**，把这一门做深。

**必做清单（至少打通 3 个）**：

1. **知识点问答**：能解释、能举例；
2. **错题录入与自动归类**；
3. **根据薄弱点生成针对性练习**；
4. **学习进度 / 掌握度记录**。

**发挥空间**：解题步骤可解释（给出过程而不只是答案）；个性化薄弱点画像；结合教材 / 课件做 RAG 并**给出引用出处**。

**最小基线**：大模型 API + 一个题库（自建 JSON 或公开题库）+ 可选接入课件做 RAG。

**横向比较关注点**：回答质量与可解释性、错题归类是否合理、生成的练习是否真的针对薄弱点。

## 通用要求

以下要求对两个选题都适用：

- **团队规模 4 人**，不允许跨方向组队；请在文档中写清每人负责的模块。
- 必须是一个**能实际运行、能交互演示**的应用，不接受只有设计文档或 PPT 的提交。
- 允许使用任何大模型 / 视觉 / 语音 API 与开源组件，但需要在 README 中写清用了什么、调用方式、API Key 如何配置（**不要把真实 Key 提交到仓库**，用 `.env` + `.env.example`）。
- 需要准备一份**可复现的演示数据**（示例账单、示例错题等），保证评审拉下代码后不用自己造数据也能跑通主流程。
- 数据库、缓存等本地依赖请做到「一条命令起服务」或在 README 中给出明确的启动步骤。

## 提交内容

1. **Git 仓库链接**（public，代码在 `main` / `master` 分支），见[根目录的提交说明](../README.md#提交方式)。
2. **README.md**：项目简介、技术栈、目录结构、环境搭建、运行命令、演示方式、分工说明。
3. **演示材料**：启动方式 + 一段简短的操作说明（截图或录屏均可，图片放仓库内并确保能显示）。如果部署了在线可访问的 Demo，附上地址。
4. **项目说明文档**（可选但推荐）：需求分析、方案设计、遇到的问题与解决方式。

## 评定说明

不设公开分数细则，评审综合判断，除[根目录的通用维度](../README.md#评定说明)外，本方向额外关注：

- 必做清单里实际打通了几项，打通的那几项**质量**如何，而不是数量堆砌；
- 自然语言理解 / 分类 / 生成的实际效果，是否能经得住评审现场提问式的测试；
- 录入与交互体验是否顺畅，异常输入（说错话、传糊图、答非所问）时怎么处理；
- 数据是否真正落库、能否持久化，而不是每次对话从零开始；
- 对越界、诱导性请求的边界处理是否合理；
- 前端 / 可视化是否可用，至少能让人看懂结果。

## 注意事项

1. **先跑通再优化**。最小基线能在半天内搭起来的话，先把端到端链路打通，再去打磨效果。
2. **数据自己造**。示例账单、错题本都可以人工构造，不需要真实用户数据，也不要去爬隐私数据。
3. **API Key 不进仓库**。用环境变量注入，README 里给出配置示例即可，提交前检查一遍提交历史。
4. **不要在答辩时现场现编**。评审可能会让你当场输入一句话、传一张图，看真实效果。
5. 时间不够时，优先保证「必做清单」至少 3 项的完整链路，再考虑发挥空间里的加分项。
